# Архитектура и инженерные соглашения React template

Документация объясняет устройство приложения, границы ответственности и правила развития кода. Она предназначена для ветки `codex/starter`, а сложные примеры взяты из реального приложения в `main`.

## Как читать

1. [Архитектура](./architecture.md) — слои, зависимости, композиция приложения и маршрутизация.
2. [Дизайн кода и данных](./code-design.md) — API, DTO, модели, состояние, hooks и use cases.
3. [Стиль кода и UI](./code-style.md) — TypeScript, React, именование, Tailwind, shadcn и доступность.
4. [Разбор реальных сценариев](./main-examples.md) — MCP Registry, встречи, генерация артефактов, подтверждение документа и SSE.
5. [Разработка и проверки](./development.md) — выбор места для нового кода, тестирование и проверка изменений.

[AGENTS.md](../AGENTS.md) — обязательные правила репозитория. Эти документы раскрывают их смысл на примерах; при расхождении приоритет имеет применимый `AGENTS.md` или `AGENTS.override.md`.

## Что уже есть в starter

Шаблон содержит React 19, TypeScript, Vite, TanStack Router и Query, Zod, Tailwind CSS, Radix-based shadcn/ui, Biome и Vitest. Основной пример — `/examples`: каталог с валидируемым поиском в URL и данными в Query-кэше. Он работает без backend благодаря mock на API-границе.

В starter уже есть `app/config/env.ts`, централизованные зависимости в `app/di`, общий HTTP transport, переключение темы и четыре UI-примитива: `Button`, `Card`, `Input`, `Label`. Запуск и контейнеризация описаны в корневом [README](../README.md).

В `main` дополнительно есть авторизация, встречи, артефакты, MCP Registry, история диалогов, редактор и другие продуктовые возможности. Они служат источником архитектурных кейсов. Документация не предполагает, что эти модули или их зависимости установлены в starter.

## Как трактовать примеры

- **Реализация** — поведение, подтверждённое исходниками указанной версии.
- **Правило** — ограничение из `AGENTS.md`, применяемое к новому коду.
- **Рекомендация** — объяснение, как применить правило в новом сценарии; это не утверждение о наличии готового модуля.

В `main` встречаются отклонения от правил: например, настроенный HTTP-клиент лежит в `shared`, но зависит от auth-фичи. Starter уже исправляет эту границу. Такие отличия явно разобраны в [архитектуре](./architecture.md#границы-main-и-starter), чтобы существующий код не становился разрешением повторять нарушение.

Материалы основаны на чтении кода и конфигурации. Они не подтверждают доступность backend, его авторизацию или успешную работу внешних интеграций.
